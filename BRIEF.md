# tiny-chess brief
main.py must become a chess engine, at most 4096 BYTES total (check: wc -c main.py), Python 3.13 stdlib only, deterministic (no clock, no random, no files). It keeps the env I/O loop of the starter (POST /game, POST /move with UCI from the env's legal_moves; env answers with the opponent reply; loop until status done). The starter's choose() is one-ply capture-greedy; replace it with a real search: own move generator on a compact board (0x88 or 10x12 mailbox), alpha-beta negamax with a FIXED NODE budget per move (about 20000-40000 nodes, ~3 s/move average max, never a clock), quiescence over captures, MVV-LVA ordering, material + simple piece-square values. Root moves must come only from the env's legal_moves list (filter root candidates by it, so castling/en passant legality is always right); inside the search pseudo-legal moves with king-capture = huge score is fine. Handle promotion (queen). Avoid repeating positions when ahead is optional. Squeeze bytes: single-letter names, no docstrings, no comments, minimal whitespace, drop the unused starter helpers.
Test locally: node /tmp/makefun/kit-tiny-chess-01/tiny-chess-01-kit/program/env/server.mjs may serve the env; read its header for how to seed it (input/env in /tmp/makefun/kit-tiny-chess-01/tiny-chess-01-kit/practice/trial-0/input/env) and run MAKEFUN_ENV_URL=http://127.0.0.1:PORT python3 main.py. If the env is hard to run, at least unit-test your engine with FENs (python3 -c ...) for legality and no crashes, and test the full loop with a tiny fake env.
Never exceed 4096 bytes. Do not git commit.
